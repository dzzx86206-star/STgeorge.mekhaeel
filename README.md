## الحالة الحالية (المرحلة 3 مكتملة)

### ✅ المرحلة 1
هيكل المشروع، تسجيل الدخول، كتاب الأجبية، تفسير الكتاب المقدس.

### ✅ المرحلة 2
نظام صلاحيات (RBAC)، الصفحة الرئيسية (Nav Drawer)، إنشاء حساب/استعادة كلمة مرور، الإعلانات (CRUD كامل)، الإعدادات (لغة/مظهر)، دعم لغتين بالكامل.

### ✅ المرحلة 3 (هذا التحديث) — المدير، الخدام، مدارس الأحد

**1. حساب المدير الثابت**
- اسم المستخدم `manager` + كلمة مرور `manager123` **أو** `manager143` → دخول فوري بصلاحيات مدير كاملة.
- تقنيًا: كلا كلمتي المرور تُسجّلان الدخول لنفس حساب Firebase Auth حقيقي واحد (يُنشأ تلقائيًا أول مرة)، والصلاحية `role: manager` تُفرض في كل تسجيل دخول فلا يمكن أن تتغير بالخطأ. (`AuthHelper.loginAsSuperAdmin`)

**2. إدارة حسابات الخدام — للمدير فقط** (`UserManagementActivity`)
- إضافة خادم (اسم مستخدم + كلمة مرور + اسم كامل + هاتف).
- تعديل الاسم/الهاتف.
- تفعيل/إيقاف الحساب (سويتش) — يمنع الدخول فورًا من داخل التطبيق.
- حذف الخادم — يمنعه من الدخول ويخفيه من كل الشاشات فورًا.
- **مهم تقنيًا**: إنشاء حساب الخادم يستخدم تطبيق Firebase ثانوي مؤقت (`AdminUserRepository`) حتى **لا يخرج المدير من جلسته** أثناء إنشاء حساب جديد — وهي مشكلة معروفة في Firebase SDK لو استُخدم التطبيق الافتراضي مباشرة.
- **قيد معروف (وليس نقص إهمال)**: "تعديل كلمة المرور" لخادم موجود غير متاحة كتغيير مباشر — لا يوجد SDK عميل (Android) يسمح لحساب بتغيير كلمة مرور حساب آخر بدون تعريض مفاتيح إدارية داخل التطبيق نفسه (ثغرة أمنية خطيرة لو استُخرجت من الـ APK). الحل المعتمد: عند نسيان الخادم لكلمة مروره، المدير يحذف حسابه وينشئ له حسابًا جديدًا بكلمة مرور جديدة — وهذا فعليًا محقق الآن بالكامل. لو احتجتم تغيير كلمة المرور الفعلي لاحقًا فهذا يحتاج Cloud Function صغيرة بصلاحيات Admin SDK (نقدر نبنيها في مرحلة قادمة لو رغبتم).

**3+4. مدارس الأحد — الفصول والأطفال** (`SundaySchoolHomeActivity`, `ClassDetailActivity`)
- المدير ينشئ الفصول (من قائمة المراحل الثابتة في المواصفات) ويربط كل فصل بخادم أو أكثر.
- الخادم يرى فصله/فصوله فقط (`SchoolClassRepository.getAssignedTo`)، والمدير والكاهن يريان كل الفصول.
- داخل كل فصل: إضافة/تعديل/حذف/بحث عن طفل، ببيانات الاسم، المرحلة، الفصل، رقم ولي الأمر، تاريخ الميلاد (اختياري)، ملاحظات.

**5+6. الحضور الأسبوعي** (`AttendanceActivity`)
- يفتح تلقائيًا على تاريخ جمعة هذا الأسبوع (`DateUtils.getCurrentFriday`).
- كل طفل له خيار حاضر ✅ / غائب ❌، وحفظ الحضور يعيد كتابة نفس يوم الجمعة لو أُعيد فتحه (بدل تكرار السجل).
- بعد الحفظ: إجمالي الأطفال، الحضور، الغياب، ونسبة الحضور.

**7. سجل الطفل** (`ChildRecordActivity`)
- كل جمعة حضر أو غاب فيها الطفل، مع إجمالي الحضور والغياب.

**8+9. صلاحيات الكاهن والمدير**
- الكاهن: يرى كل الفصول والأطفال وتقارير الحضور (بدون التحكم في إنشاء الفصول أو حسابات الخدام)، ويقدر يعدّل بيانات الأطفال والحضور مباشرة.
- المدير: كل الصلاحيات بدون استثناء — إدارة المستخدمين، الفصول، الأطفال، التقارير.

## ⚠️ إعداد Firestore المطلوب لهذه المرحلة

بعض الاستعلامات الجديدة تحتاج **فهارس مركّبة (Composite Indexes)** في Firestore، وهي مش هتشتغل من غير ما تُنشأ. أسهل طريقة: شغّل التطبيق وجرّب كل شاشة من دول، Firestore هيرمي خطأ في الـ Logcat فيه **رابط مباشر** لإنشاء الفهرس بضغطة واحدة:
- شاشة "مدارس الأحد" (كخادم).
- شاشة تفاصيل الفصل (بحث/عرض الأطفال).
- سجل الطفل (تاريخ الحضور).
- إدارة الخدام.

## أول استخدام لحساب المدير
افتح شاشة الدخول واكتب:
- اسم المستخدم: `manager`
- كلمة المرور: `manager123` (أو `manager143`)

هيتنشئلك الحساب تلقائيًا أول مرة — مفيش خطوات يدوية في Firebase Console مطلوبة له بعد النهاردة.

قولّي لما تجرب المرحلة دي، ونحدد أي قسم من "لسه محتاج بناء" نبدأ بيه.

## ✅ المرحلة 3.1 — تحديث أمان (إدارة الخدام: إضافة وحذف فقط)

بناءً على طلبكم، لوحة "إدارة الخدام" أصبحت **إضافة وحذف فقط** — تم حذف زر التعديل ومفتاح تفعيل/إيقاف الحساب نهائيًا من الواجهة.

### ⚠️ الأهم: ملف قواعد الأمان (Firestore Security Rules) — لازم تنزّله

اكتشفت إن المشروع من البداية معندوش **ملف قواعد أمان لقاعدة بيانات Firestore** (`firestore.rules`). ده أهم حاجة أمنية في أي تطبيق Firebase: أي فحص صلاحيات داخل التطبيق نفسه (زي RBAC في `NavProvider`) هو للواجهة بس — مش حماية حقيقية، لأن أي حد يقدر يتكلم مباشرة مع Firestore API من غير ما يمر بالتطبيق أصلًا ويتجاوز أي فحص داخل الكود. القواعد دي هي اللي فعليًا بتمنع أو تسمح بالقراءة/الكتابة على مستوى السيرفر.

أضفت ملف `firestore.rules` في جذر المشروع بيطبّق نفس نظام الصلاحيات لكن **من جهة السيرفر**:
- بيانات كل مستخدم يقدر يقرأها هو بس أو الكاهن/المدير.
- حساب المدير الثابت (`manager@stgeorge.church`) هو الوحيد اللي يقدر يمنح نفسه `role: manager`.
- الخادم الجديد (`إنشاء حساب`) ميقدرش يمنح نفسه أي دور غير `member`.
- المدير بس يقدر يضيف حساب بدور `servant`، وبس يقدر يحذف حسابات بدور `servant` (مش أي حساب تاني).
- باقي المجموعات (الإعلانات، الفصول، الأطفال، الحضور) محمية حسب الدور.

**لازم** تنزّل الملف ده على مشروعك (مجاني تمامًا، بيشتغل على خطة Spark المجانية):
```
firebase login
firebase use --add        # اختر مشروع Firebase بتاعك
firebase deploy --only firestore:rules,firestore:indexes
```
(محتاج تنصيب Firebase CLI مرة واحدة: `npm install -g firebase-tools`)

ملف `firestore.indexes.json` جنبه بيحل مشكلة الفهارس المركّبة اللي كانت محتاجة تتعمل يدوي من قبل — هتتنشأ تلقائيًا مع نفس الأمر.

### حذف حساب الخادم — إزاي بيشتغل بأمان بدون أي مفتاح سري في التطبيق

- الضغط على "حذف" بيمسح بيانات الخادم من Firestore فورًا — وده لوحده كافي يمنعه تمامًا من الدخول للتطبيق (`AuthHelper` بيرفض تسجيل الدخول لأي حساب مالوش بيانات في Firestore).
- بعد كده التطبيق بيحاول (best effort) ينادي Cloud Function اسمها `deleteServantAuth` عشان تمسح حساب الدخول (Firebase Authentication) نهائيًا كمان. **الفانكشن دي اختيارية تمامًا** — لو مش موجودة، محاولة النداء بتفشل بصمت والتطبيق شغال عادي وآمن زي ما هو.
- لو نزّلتوها (اختياري):
  ```
  cd functions
  npm install
  firebase deploy --only functions
  ```
  ⚠️ نشر Cloud Functions محتاج **خطة Firebase Blaze** (الدفع حسب الاستخدام)، وفيها حد مجاني كبير كفاية لاستخدام كنيسة عادي، لكن لازم تربط وسيلة دفع. لو مش عايزين الالتزام ده، متعملوش الخطوة دي — التطبيق آمن ومكتمل الوظائف من غيرها، وبس اسم المستخدم بتاع خادم محذوف مش هيتقدر يتكرر تاني (هيظهر رسالة واضحة توضح ده وتقترح اسم مستخدم مختلف).
- **مفيش أي مفتاح Admin SDK أو Service Account داخل التطبيق نفسه في أي وقت** — الفانكشن دي بتشتغل على سيرفرات Google جوه مشروعكم بس، وبتتأكد من صلاحية المستخدم اللي بينادي عليها (لازم يكون مدير) قبل ما تعمل أي حاجة.
